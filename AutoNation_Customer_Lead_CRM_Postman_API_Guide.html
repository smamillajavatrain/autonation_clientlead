Execution order: Start the application, create account managers first, then create leads. Use the actual IDs returned by the APIs in subsequent requests.

1. Account Manager APIs

Create Account Manager

POST
http://localhost:8080/api/account-managers
Content-Type: application/json
{
  "name": "Paul Manager",
  "email": "Paul.manager@example.com",
  "phone": "9876500000"
}
curl --location 'http://localhost:8080/api/account-managers' \
--header 'Content-Type: application/json' \
--data '{
  "name": "Paul Manager",
  "email": "Paul.manager@example.com",
  "phone": "9876500000"
}'

2. Customer Lead APIs

Create Customer Lead

POST
http://localhost:8080/api/leads
Content-Type: application/json
Idempotency-Key: 11111111-1111-1111-1111-111111111111
{
  "name": "Srikanth Mamillapalli",
  "email": "smamilla1208@outlook.com",
  "phone": "9876543210",
  "comment": "Interested in a new vehicle"
}
curl --location 'http://localhost:8080/api/leads' \
--header 'Content-Type: application/json' \
--header 'Idempotency-Key: 11111111-1111-1111-1111-111111111111' \
--data '{
  "name": "Srikanth Mamillapalli",
  "email": "smamilla1208@outlook.com",
  "phone": "9876543210",
  "comment": "Interested in a new vehicle"
}'
Save the returned lead ID. The following examples assume lead ID 1.

Get Customer Lead

GET
http://localhost:8080/api/leads/1
curl --location 'http://localhost:8080/api/leads/1'

3. Duplicate Submission / Idempotency

Submit the Same Lead Again

Send the same Idempotency-Key to represent the same logical HTTP submission.

curl --location 'http://localhost:8080/api/leads' \
--header 'Content-Type: application/json' \
--header 'Idempotency-Key: 11111111-1111-1111-1111-111111111111' \
--data '{
  "name": "Srikanth Mamillapalli",
  "email": "smamilla1208@outlook.com",
  "phone": "9876543210",
  "comment": "Interested in a new vehicle"
}'
The application checks the key before creating another lead. The database UNIQUE constraint also protects against concurrent duplicate inserts.

5. Alternative Outcomes

Close During Initial Call – CANT_MEET_NEED

curl --location 'http://localhost:8080/api/leads' \
--header 'Content-Type: application/json' \
--header 'Idempotency-Key: 22222222-2222-2222-2222-222222222222' \
--data '{
  "name": "Kalyani Mamillapalli",
  "email": "KalyaniMamillapalli@example.com",
  "phone": "9876543211",
  "comment": "Required product is not available"
}'
curl --location --request PUT 'http://localhost:8080/api/leads/2/assign' \
--header 'Content-Type: application/json' \
--data '{"accountManagerId":1,"assignedById":1}'
curl --location --request PUT 'http://localhost:8080/api/leads/2/initial-call'
curl --location --request PUT 'http://localhost:8080/api/leads/2/close' \
--header 'Content-Type: application/json' \
--data '{
  "reason": "CANT_MEET_NEED",
  "comments": "Required product is not available"
}'

Close After Present Proposal – NO_SALE

The lead must first follow NEW → ASSIGNED → INITIAL_CALL → PROPOSAL → PRESENT_PROPOSAL.

curl --location --request PUT 'http://localhost:8080/api/leads/3/close' \
--header 'Content-Type: application/json' \
--data '{
  "reason": "NO_SALE",
  "comments": "Customer decided not to proceed"
}'

9. Validation and Error Scenarios

Validation Error

curl --location 'http://localhost:8080/api/leads' \
--header 'Content-Type: application/json' \
--data '{
  "name": "",
  "email": "invalid-email",
  "phone": "12",
  "comment": "Test"
}'

Expected: 400 BAD_REQUEST

{
  "errorCode": "COMMON-001",
  "message": "Request validation failed",
  "path": "/api/leads",
  "fieldErrors": {
    "name": "Name is required",
    "email": "Email must be valid",
    "phone": "Phone must contain 7 to 20 valid phone characters"
  }
}

Lead Not Found

curl --location 'http://localhost:8080/api/leads/99999'

Expected: 404 NOT_FOUND

{
  "errorCode": "LEAD-001",
  "message": "Customer lead not found: 99999",
  "path": "/api/leads/99999"
}

Invalid Lifecycle Transition

Example: attempting to move a NEW lead directly to PROPOSAL.

curl --location --request PUT 'http://localhost:8080/api/leads/4/proposal'

Expected: 400 BAD_REQUEST

{
  "errorCode": "LEAD-002",
  "message": "Cannot change lead status from NEW to PROPOSAL",
  "path": "/api/leads/4/proposal"
}
